# ACL 2027 Research Workspace

## Working title

**Safe Continual Skill Routing for LLM Agents under Budget and Non-Regression Constraints**

## Central question

How can an agent safely retrieve and update rules from a continually growing skill library while respecting a prompt-token budget and avoiding regressions on previously learned domains?

## Current position

The current repository is an engineering-complete pilot, not yet a submission-ready paper. MOAR/NSGA-II is treated as a baseline until scaling experiments demonstrate a defensible Pareto advantage over BM25, dense retrieval, greedy selection, and online bandit routing.

For a repository-backed snapshot of the current work, see [`CURRENT_STATUS.md`](CURRENT_STATUS.md). The chronological phase log is [`EXPERIMENT_LOG.md`](EXPERIMENT_LOG.md). As of **August 10, 2026**, 18 phases are persisted through Phase 1K; Phase 1L is planned but its exactly-four-call paid confirmation remains unauthorized.

## Offline selector-scaling diagnostic

The generated 8/16/32/64-rule selector-only proxy is documented in `notes/router_scaling_proxy_v1.md`. It makes no model calls and must not be cited as task accuracy. The current result keeps MOAR as a baseline: frozen-utility greedy routing is substantially faster and preserves the known SearchQA base set more reliably, but benefits from an explicit known-base utility prior that requires cold/noisy/adversarial follow-up tests.

## Phase 0A continual-routing diagnostic

The complete 96-run synthetic offline grid is documented in `results/phase0a_offline_continual_v1.md`. The harness validates online credit, cumulative token accounting, regret, calibration, corruption conditions, and forgetting. It currently shows that leave-one-out credit costs about 2.5? more tokens without improving reward, and that global utility methods do not yet beat relevance Top-K. Paid API experiments remain blocked until contextual credit and non-regression gates improve this result.

## Research questions

- **RQ1 — Scale:** How do retrieval quality, latency, and token efficiency change as the rule library grows from 8 to 32, 128, and 512 rules?
- **RQ2 — Credit:** Does per-rule online credit assignment outperform shared batch credit?
- **RQ3 — Safety:** Can a cross-domain non-regression gate reduce forgetting during continual skill evolution?
- **RQ4 — Complexity:** When is a multi-objective evolutionary selector worth its latency relative to simple retrieval and greedy methods?

## Non-claims

Until supported by new experiments, the paper must not claim that:

- MOAR is the most accurate selector;
- three declared seeds are independent when outputs were copied;
- results generated by an older commit reproduce the current implementation;
- small eight-rule experiments demonstrate large-library scalability.

## Evidence gates before submission

1. Artifact audit has zero unresolved errors for all paper tables.
2. Every main-table run has a unique run ID and independent output fingerprint.
3. At least three task families, including one multi-step tool-use task.
4. At least two model families and three independent runs per main condition.
5. Library scaling reaches at least 128 non-duplicated rules.
6. Strong lexical, dense, greedy, bandit, exact-small-N, and full-skill baselines.
7. Fast/Slow and four-objective ablations use one frozen code/config version.

## Cross-conversation resume

The ACL 2027 experiment program persists in repository files rather than chat memory. At the start of a new conversation, run:

```powershell
python scripts/acl2027_experiment_handoff.py validate
python scripts/acl2027_experiment_handoff.py status
```

Use `python scripts/acl2027_experiment_handoff.py handoff` to generate a compact recovery prompt. The machine-readable source of truth is `experiment_state.json`; completed configs and artifact manifests remain immutable.

## Directory policy

- `../../scripts/acl2027_experiment_handoff.py`: validates state and emits status or a recovery prompt.
- `outline.md`: paper argument and section-level claims.
- `experiment_roadmap.md`: complete evidence plan, phased execution path, metrics, baselines, and submission gates.
- `phase0_execution_plan.md`: executable Phase 0A?0C milestones and decision gates.
- `experiment_registry.csv`: one row per immutable run.
- `results/`: generated tables only; never hand-edit reported numbers.
- `notes/`: related-work and reviewer-risk notes.
